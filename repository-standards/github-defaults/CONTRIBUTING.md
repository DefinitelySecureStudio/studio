# Contributing

Thank you for contributing to Definitely Secure Studio projects. Each
repository README defines its responsibility and content boundary; read it
before proposing work.

## Before opening a change

1. Search existing issues and pull requests.
2. Open or reference an issue for work that changes behavior, policy, contracts,
   canon, or maintained output.
3. Confirm the work belongs in this repository.
4. Read the repository's license, security policy, and any local contribution
   override.
5. Keep private lore, unreleased creative material, credentials, personal data,
   vulnerability details, and confidential communications out of public GitHub
   content.

## Pull requests

Use a focused branch and complete the pull-request template. Explain the change,
why it belongs here, user or contributor impact, validation, dependencies, and
any security, licensing, data, or creative-IP considerations. Update tests,
documentation, and changelog entries when applicable.

Identify third-party material and preserve its license, provenance, and notice
requirements. Do not submit work you do not have the right to contribute. The
repository's local contribution and license terms control if they are more
specific than this default.

Be responsive to review and keep the branch current when requested. A pull
request is not accepted until required owners approve it and it is merged.

## Sensitive reports

Never open a public issue for a suspected vulnerability, leaked secret, private
lore disclosure, or other sensitive incident. Follow `SECURITY.md` instead.
